# 域名与关联邮箱管理

管理员在“系统设置 → 域名管理”中启停域名、移除配置和查看关联邮箱。
主管理员还可以提交永久清理任务。功能对应 [Issue #23](https://github.com/mibgb65-cloud/OmniMail/issues/23)。

## 操作影响

| 操作 | 历史数据 | 后续使用 |
| --- | --- | --- |
| 停用域名 | 邮箱、邮件、草稿和附件保留 | 停止新收发、地址创建和邀请注册 |
| 移除配置 | 邮箱、邮件、草稿和附件保留，可读取历史 | 相关邀请失效，停止该域名的新操作 |
| 清理选中邮箱 | 永久删除选中邮箱的邮件、草稿和附件 | 其他邮箱按原域名状态工作；清理后地址释放 |
| 清理全部关联邮箱并移除配置 | 永久删除所有目标邮箱的主存储数据 | 清理完成后移除域名配置，使相关邀请失效 |

这些操作不修改 Cloudflare DNS、MX 或 Email Routing，不删除外部 Provider 账号和远端邮件。
备份仍按原保留策略保存。重新添加已移除的域名，可以恢复仍启用的保留邮箱，不能恢复永久清理的数据。
停止后续发信不等于撤回外部邮件服务已经接收的邮件。

## 查看与清理流程

1. 点击域名旁的邮箱数量或“查看关联邮箱”，查看所属用户、主邮箱与清理状态。
2. 主管理员勾选当前页的可清理邮箱，点击“清理选中邮箱”；整域操作使用独立入口。
3. 查看服务端预览，核对涉及用户、邮箱、邮件、草稿、附件和预计释放空间。
4. 输入完整域名，点击“提交清理任务”。提交成功表示任务已保存，实际清理由后台完成。
5. 在面板中查看进度；可以关闭页面，之后重新打开该域名的关联面板查询。
6. 失败时使用“重试清理任务”，继续原任务未完成部分。已经删除的数据不会恢复。

关联列表默认每页 50 条，最多 100 条。选中清理每次最多 100 个地址；整域任务由服务端确定完整范围，
不会把当前页全选当成全域。预览十分钟内有效；提交时归属、主邮箱或全域目标变化会要求重新预览。

主邮箱不能清理，必须先由所属用户设置其他可用的主邮箱。全域操作包含主邮箱或已有个人清理记录时，
应先处理这些阻塞项；系统不会静默跳过并宣称域名已清空。
同一域名只运行一份管理清理任务，期间配置操作会被拒绝。

无人收件保存于共享系统邮箱，不属于关联邮箱。它的历史数据不包含在此清理范围内，
预览会展示保留数量；不会删除 `__unassigned__@omnimail.invalid`。

## 权限与接口兼容

普通管理员可以查看关联记录、停用域名和移除配置，批量清理、任务详情与重试仅允许主管理员访问。
原个人邮箱接口继续按当前用户和原权限规则执行。

`DELETE /api/admin/domains/{name}` 无参数时仍只删除空域名。
网页使用显式 `mode=configuration` 移除配置并保留历史数据；旧客户端不会被升级成级联删除。
批量任务使用预览返回的 `jobId` 作为幂等身份，重复提交不能扩大原目标集合。

接口参数和示例见 [管理员域名 API](api/admin-access.md)。

## 数据库迁移与部署

本功能新增 `0041_domain_mailbox_cleanup.sql`，包括清理任务、目标快照、对象关联、邮箱归属标记和并发保护触发器。
运行时恢复迁移与 CLI 迁移保持一致；复用已有 `CLEANUP_WORKFLOW` 绑定，不增加 Secret 或 Cloudflare 服务。

本地验证：

```powershell
npm run db:migrate:local
npm run test:worker -- email-worker/integration/domain-mailbox-cleanup.integration.ts
npm run test:e2e -- e2e/domain-mailbox-management.e2e.ts
npm run build
```

部署沿用仓库入口，由部署脚本先处理 D1 迁移：

```powershell
npm run deploy
```

不得仅运行 `npx wrangler deploy` 而忽略迁移。部署后使用测试域名与非主邮箱验证真实 Workflow 的派发、
分批处理、对象失败补偿和任务收尾，再在承载重要数据的域名使用永久清理。

## 任务恢复与回滚

- 派发意图先记录在 D1。创建 Workflow 失败时，任务仍可查询，现有调度入口与页面重试可以恢复派发。
- 任务使用确定的实例 ID。创建成功但响应丢失时核对同一实例；实例已终止或失败时允许新尝试恢复。
- 配额扣减和删除待办沿用既有事务；R2 删除失败保留对象待办，未处理完不能标记清理成功。
- 全域任务启动后域名保持停用；失败时配置保留并冻结，继续重试。选中任务不改变其他邮箱的收发状态。
- 新任务期间不允许重新激活目标邮箱、切换目标为主邮箱或改变其归属；已经排队的收发与通知会检查目标状态。
- 回滚先关闭新任务入口，并让活动任务由兼容版本完成。存在活动任务时不能直接切换到不认识
  `domainCleanup` 参数和归属标记的旧 Worker。
- 回滚保留新表和迁移记录，避免丢失目标与进度；旧任务重放不能影响清理后重新分配的地址。

首次删除前的启动异常不会自动恢复为可用状态，任务保留冻结并等待派发恢复或显式重试。
这是为了避免“远端创建成功但响应丢失”时，邮箱重新开放并与后台删除并发。
