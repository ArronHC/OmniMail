### 更新摘要

- 修复新部署配置了统一邮箱密钥后，NAVER、Yandex 仍显示“功能尚未启用”的问题。
- 两个邮箱入口默认显示，管理员可直接在系统设置中隐藏或恢复入口，无需配置额外环境开关。

### 修复

- 移除 `NAVER_MAIL_IMAP_ENABLED`、`YANDEX_MAIL_IMAP_ENABLED` 的配置依赖与运行时判定。
  有效的 `MAIL_CREDENTIALS_KEY` 或对应旧独立密钥即可启用账号连接、邮件读取和后台同步。
- NAVER、Yandex 的导航入口默认开启，前后端默认值保持一致；系统设置只控制入口是否显示。
- 保留已有管理员隐藏设置，升级不会重新打开已主动隐藏的入口；隐藏入口不会删除账号、密文或邮件索引。
- 同步更新设置指南，说明自动启用、入口显示和后台同步之间的关系。

### 升级说明

1. Web `1.1.1` 可直接升级，**不新增 D1 迁移、变量、Secret、资源绑定或 API 变更**。
   已配置有效邮箱密钥的实例无需额外操作，继续沿用原密钥。
2. 更新自己的 Fork，构建命令使用 `npm run build`，部署命令使用 **`npm run deploy`**。
3. 两个旧 IMAP 环境开关不再生效，包括残留的 `false`，可从 Worker 配置中清理。
   如果原来依赖这些开关暂停已有账号，升级后相关账号会恢复后台同步。
4. 在 **系统设置 → 邮箱功能入口** 关闭 NAVER 或 Yandex 只隐藏入口，不禁用 API 或停止已有账号同步。
   需要停止某个账号时，请在账号管理中断开该账号；系统设置中已保存的隐藏状态会继续保留。
5. 本次只发布 Web 补丁版本，Float 和 Android 继续使用独立版本号。
