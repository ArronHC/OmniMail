### 更新摘要

- 域名管理新增关联邮箱列表，可直接查看所属用户、主邮箱和清理状态，解决删除入口难找的问题。
- 明确区分“移除域名配置”和“永久清理邮箱”：移除配置保留历史数据，主管理员可批量清理选中邮箱或整个域名的关联邮箱。
- 批量清理由后台任务执行，支持刷新后查询进度与失败重试，并保护主邮箱和其他用户的数据边界。

### 新增

- 域名关联邮箱支持服务端分页和当前页多选，展示所有关联用户、主邮箱标记与清理中记录。
- 主管理员可预览清理影响，核对用户、邮箱、邮件、草稿、附件及预计释放空间，并输入完整域名确认。
- 清理任务、目标快照和对象待办持久化到 D1；复用现有 Cleanup Workflow 分批处理，页面关闭后仍可继续。
- 增加进度查询、原任务重试和审计记录，避免把任务提交成功误报为数据已经全部删除。

### 改进

- 网页的常规移除动作仅删除 OmniMail 域名管理配置，保留关联邮箱及其邮件、草稿和附件。
- 停用或移除域名后明确停止后续新收发、邮箱创建及邀请注册；保留邮箱显示“域名不可用 · 历史可读”。
- 更新域名后同步刷新个人邮箱状态；确认弹窗支持域名文本输入、完整键盘焦点循环和弹窗内错误提示。
- 同步中英文界面、API 参考、使用说明和迁移说明。

### 修复

- 修复清理预览过期回收与提交并发时可能报错并停用域名的问题；提交事务会核对任务状态，失效预览不会留下域名冻结或审计误报。

### 安全

- 批量清理、任务详情和重试仅允许主管理员使用；普通管理员可以查看关联记录和移除配置。
- 主邮箱必须先由所属用户迁移，批量清理不会绕过这一保护；已有个人清理记录会阻止重复接管。
- 预览绑定操作者与目标范围，提交时重新校验主邮箱、归属和范围；重复提交同一任务不扩大清理范围。
- 清理期间冻结目标写入与域名配置操作，已排队的收发、通知及账号清理检查目标状态。
- 复用配额事务和 R2 删除补偿；对象未清理完成时不宣称成功，旧任务重放不会删除重新分配的地址。

### 升级说明

1. 从 Web `1.2.0` 升级前备份 D1 和现有部署配置，更新代码后依次运行 `npm run build`、
   `npm run deploy`。部署脚本先应用 `0041_domain_mailbox_cleanup.sql`，再发布 Worker 与前端。
   不要仅运行 `npx wrangler deploy` 而遗漏数据库迁移。
2. 复用已有 `CLEANUP_WORKFLOW` 绑定，不增加 Secret、环境变量或 Cloudflare 服务；原有邮箱连接无需重新绑定。
3. 原 `DELETE /api/admin/domains/{name}` 无参数时仍只删除空域名；网页通过显式
   `mode=configuration` 移除配置并保留历史数据，旧客户端不会被升级为级联删除。
4. 永久清理包括目标邮箱的历史邮件、草稿、附件、原始邮件和翻译缓存。备份按既有保留策略保存；
   共享系统邮箱中的无人收件历史邮件不包含在本次清理范围内，预览会展示保留数量。
5. 本功能不修改 Cloudflare DNS、MX 或 Email Routing，不删除外部邮箱账号或远端邮件。
   重新添加同名域名可以恢复仍启用的保留邮箱，不能恢复永久清理的数据。
6. 回滚前停止创建新任务，并由兼容版本完成活动清理。存在活动任务时不能直接回滚到不识别
   `domainCleanup` 参数和清理标记的旧 Worker；保留新增表、字段及迁移记录。
7. 详细操作与恢复步骤见
   [域名与关联邮箱管理](https://github.com/mibgb65-cloud/OmniMail/blob/v1.3.0/docs/DOMAIN_MAILBOX_MANAGEMENT.md)。
